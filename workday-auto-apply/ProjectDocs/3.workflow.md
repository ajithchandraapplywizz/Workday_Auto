# Workflow — Workday Auto-Apply Bot

Two operating modes share one core engine: **Local Phase** (terminal-driven, single user) and **Production Phase** (Telegram + Supabase-driven, multi-user). Production Phase wraps the same scan → match → fill → submit engine with a notification/approval shell.

---

## 1. Local Phase — End-to-End Flow

```
START
  │
  ▼
Read job URLs from file (targets.txt)
  │
  ▼
FOR each URL:
  │
  ▼
[LOCAL-1] Open URL (headed browser)
  │
  ├─ Sign-in/sign-up required? ──Yes──▶ Detect popup/interstitial type
  │                                        │
  │                                        ▼
  │                                Auto-click correct path
  │                                (sign in with email / create account)
  │                                        │
  │                                        ▼
  │                                Enter stored credentials
  │                                        │
  │                                        ▼
  │                                Handle post-auth redirect
  │
  └─ No ───────────────────────────────────┘
  │
  ▼
[LOCAL-2] Scan current page via DOM + accessibility tree
  │        (screenshot taken in parallel — audit only, not decisioning)
  ▼
For each detected question/field:
  │
  ├─ Fuzzy-match label against Q&A cache ──Hit (≥ threshold)──▶ Apply cached answer ─▶ verify in DOM
  │
  ├─ Miss, but factual field (name/edu/exp) ──▶ Pull from resume/profile ─▶ verify
  │
  ├─ Miss, optional/non-required ──▶ Skip
  │
  └─ Miss, required, no source ──▶ [LOCAL-3] Escalate
                                        │
                                        ▼
                              Pause. Prompt operator in terminal.
                                        │
                                        ▼
                              Apply typed answer to field
                                        │
                                        ▼
                              Persist Q&A pair to cache (this user, forever)
  │
  ▼
All required fields on page filled + verified?
  │
  ├─ No ──▶ retry empties (bounded retries) ──▶ back to scan
  │
  └─ Yes
       │
       ▼
  Click "Save and Continue"
       │
       ▼
  Wait for next page state (heading/URL/progress-bar change)
       │
       ▼
  Is current heading "Review"? ──No──▶ loop back to [LOCAL-2]
       │
      Yes
       │
       ▼
  Cross-check Review summary vs intended values
       │
       ▼
  Auto-submit
       │
       ▼
  Screenshot + log result to CSV (status, company, url, ats, timestamp)
       │
       ▼
  NEXT URL in file
       │
       ▼
      END
```

### Failure path (applies at any step)
```
Exception raised
  │
  ▼
Catch → log (url, timestamp, stack) → screenshot → close browser cleanly
  │
  ▼
Continue to next URL (do not crash whole batch)
```

## 2. Production Phase — End-to-End Flow

```
START
  │
  ▼
User scans onboarding QR (deep-link → t.me/<bot>?start=<token>)
  │
  ▼
Telegram bot asks for email → maps to Supabase user record
  │
  ▼
Bot retrieves stored Workday credentials for that user from Supabase
  │
  ▼
Bot logs into Workday automatically (same engine as Local Phase)
  │
  ▼
Telegram message: "You're logged in ✅"
  │
  ▼
Bot filters Supabase job-link pool → only links matching user's domain
  │
  ▼
Telegram message: "New eligible job: <role> @ <company> — Apply?"
  │
  ├─ User declines ──▶ mark skipped in Supabase, no action
  │
  └─ User approves
       │
       ▼
  Run core engine (scan → match → fill) against that job URL
       │
       ▼
  For each unknown question:
       │
       ├─ Fuzzy-match Supabase Q&A table (this user) ──Hit──▶ apply
       │
       ├─ Miss ──▶ attempt resume-parse inference ──Hit──▶ apply
       │
       └─ Miss ──▶ send question to user via Telegram
                        │
                        ▼
                  User replies once
                        │
                        ▼
                  Apply answer + INSERT new row into Supabase Q&A table
                  (permanent, reused for all future applications, this user)
       │
       ▼
  Review + auto-submit (same as Local Phase)
       │
       ▼
  Write status to Supabase: submitted / needs_review / rejected_ineligible / failed
       │
       ▼
  Telegram message with final status
       │
       ▼
  Repeat for next matched job (respecting daily cap + dedup window)
       │
       ▼
      END (per user; runs independently per concurrent user)
```

## 3. State Detection (shared by both phases)

Workday wizard step is never assumed from run start — detected fresh every time from page heading + progress bar + URL:

```
IF heading == "My Information"        → handle My Information step
ELIF heading == "My Experience"       → handle My Experience step
ELIF heading == "Application Questions" → handle Application Questions step
ELIF heading == "Voluntary Disclosures" → handle Voluntary Disclosures step
ELIF heading == "Review"              → validate + submit
ELSE                                  → capture diagnostics, raise, stop (no guessing)
```

This makes the bot **resumable from any step**, which matters because Production Phase runs may be interrupted (e.g. waiting on a Telegram reply for an unknown question) and must pick back up without restarting the whole application.

## 4. Module Ownership Map

| Flow stage | Owning module | Shared across phases? |
|---|---|---|
| Link intake | `discovery.mjs` | Yes (file-based in Local, DB-based in Production) |
| Auth | `workday.mjs` | Yes (credentials sourced from `.env`/`profile.yml` locally, Supabase in Production) |
| DOM scan | `scanner.mjs` / `workdayDom.mjs` | Yes |
| Field/answer matching | `planner.mjs` + `qaStore.mjs` | Yes (`qaStore.mjs` backed by local YAML in Local Phase, Supabase table in Production) |
| Fill + verify | `engine.mjs`, `fields.mjs` | Yes |
| Escalation to human | terminal `input()` (Local) → Telegram message (Production) | Same trigger logic, different I/O channel |
| Submit + report | `reporter.mjs` | Yes (CSV in Local, Supabase + Telegram in Production) |
| Notification | — (none in Local) | Telegram bot layer, Production only |
| Job matching | — (manual file in Local) | Supabase domain-filter query, Production only |
